# Configuration File Guide

All core rules of the engine are stored within JSON files. This guide explains how to load these files and details the structural format of each. For **available values** of each field, see the [JSON Value Reference Table](./07_json_value_reference.md).

---

## 1. Two Ways to Load JSON Files

### Method A: Embedded as Dart Strings (Recommended, ideal for packaging/publishing)

Pre-compile the JSON content into Dart `const String`s and bundle them directly into the library. The benefits are direct referencing, zero I/O overhead, and it's heavily suited for Flutter/Pure Dart cross-platform distribution.

This is exactly how the default ruleset of this library operates (see `lib/src/config/default_jsons.dart`). You can use the [Compilation Tool](#3-using-the-compilation-tool-to-convert-json-to-dart-files) to automatically generate this file.

Once generated, pass them to `ConfigLoader`:
```dart
// Your own MyJsons class (generated by the compile tool)
final ruleset = ConfigLoader.createRuleset(
  starsJson: MyJsons.stars,
  sihuaJson: MyJsons.sihua,
  flowJson: MyJsons.flowStars,
  mainRulesJson: MyJsons.mainRules,
);
```

### Method B: Read Files at Runtime (Ideal for Servers / Hot-Updates)

For server environments or scenarios requiring dynamic rule loading, you can read the JSON directly from the file system:

```dart
import 'dart:io';

final starsJson = await File('assets/config/my_rules/stars.json').readAsString();
final sihuaJson = await File('assets/config/my_rules/sihua.json').readAsString();
// ...

final ruleset = ConfigLoader.createRuleset(
  starsJson: starsJson,
  sihuaJson: sihuaJson,
  // ...
);
```

## 2. Format Specifications for Each Configuration File

The default configuration files are located under `assets/config/default/`, totaling 6 files.

### 1. `stars.json` — Origin Chart Star Placement Rules

A JSON array where each item defines the placement logic for a single star.

```json
[
  {
    "key": "taiyang",
    "type": "major",
    "rule": {
      "type": "anchor_offset",
      "anchor": "ziwei",
      "offset": -3
    }
  }
]
```

`rule.type` supports the following:

| Type | Description |
| :--- | :--- |
| `anchor_offset` | Calculate based on an anchor star, shifting forward/backward by a number of palaces |
| `lookup` | Lookup via year stem/branch, landing directly in a specific palace |
| `lookup_offset` | Lookup via a table, then apply an offset |
| `constant` | Fixed to a specific palace branch |
| `pipeline` | Chain multiple rules consecutively (Composite rules) |

Examples of permissible `anchor` values: `ziwei`, `tianfu`, `year_stem`, `year_branch`, `hour`, `birth_month`, etc.

---

### 2. `sihua.json` — SiHua (Four Transformers) Rules

Nested structure: Stem → SiHua Type → Star Key:

```json
{
  "jia": { "lu": "lianzhen", "quan": "pojun", "ke": "wuqu",  "ji": "taiyang" },
  "yi":  { "lu": "tianji",   "quan": "tianliang", "ke": "ziwei", "ji": "taiyin" }
}
```

Stem Pinyin: `jia/yi/bing/ding/wu/ji/geng/xin/ren/gui`  
SiHua Types: `lu/quan/ke/ji`  
Values are Star Keys (e.g., `ziwei`, `tianji`, `taiyang`...)

---

### 3. `brightness.json` — Star Brightness Options

Star Key → Array of 12 brightness values (Index 0 = Zi [子] Palace, moving sequentially to Hai [亥] Palace):

```json
{
  "ziwei":   [2, 6, 6, 5, 4, 5, 6, 6, 5, 5, 4, 5],
  "taiyang": [0, 1, 5, 6, 5, 5, 5, 4, 4, 2, 1, 0]
}
```

The brightness system consists of two synchronized layers:

**First Layer (Here)**: The numbers in `brightness.json` are mere **integer keys** representing a brightness tier. By default, `0`~`6` and `-1` are used, but these can be completely customized.

**Second Layer**: The `brightness_labels` in `main_rules.json` maps the above integer keys to the final output JSON string field (e.g., `"level_miao"`). During the Star's `toJson` export, the engine replaces the number with its corresponding label string. `-1` denotes "No Brightness Label" (omits the field entirely).

Default Maps: `6`=`level_miao` `5`=`level_wang` `4`=`level_de` `3`=`level_li` `2`=`level_ping` `1`=`level_bu` `0`=`level_xian` `-1`=None

**Customizing Brightness Tier Example**: If you wanted to add a tier `7`=Extreme Miao:

In `brightness.json` use `7`:
```json
{ "ziwei": [7, 6, 6, 5, ...] }
```

Declare it in `main_rules.json`:
```json
{
  "brightness_labels": {
    "7": "level_extreme_miao",
    "6": "level_miao",
    ...
  }
}
```

> [!IMPORTANT]
> All numbers used in `brightness.json` (except `-1`) MUST be defined within `main_rules.json`'s `brightness_labels`, otherwise the engine evaluates it as malformed and throws a `FormatException`.

---

### 4. `flow_stars.json` — Flow Timeline Dynamic Stars

Dynamic stars layered during flowing constraints. The format is similar to `stars.json`, packed with an independent brightness array:

```json
[
  {
    "key": "flow_lucun",
    "rule": {
      "type": "lookup",
      "anchor": "year_stem",
      "table": {
        "jia": 2, "yi": 3, "bing": 5, "ding": 6, "wu": 5,
        "ji": 6, "geng": 8, "xin": 9, "ren": 11, "gui": 0
      }
    },
    "brightness": [6, 6, 6, 6, 6, 6, 6, 6, 6, 6, 6, 6]
  }
]
```

---

### 5. `main_rules.json` — Calendar Toggles & Brightness Maps

```json
{
  "calendar": {
    "split_rat_hour": false,
    "leap_month_strategy": "split",
    "wu_hu_dun_boundary": "lunar",
    "sihua_boundary": "lunar",
    "childhood_decade": "skip",
    "flowLimit_boundary": "lunar",
    "enable_historical": true
  },
  "brightness_labels": {
    "6": "level_miao",
    "5": "level_wang",
    "0": "level_xian",
    "-1": "level_none"
  }
}
```

**`calendar` Available Options:**

| Field | Type | Available Options | Description |
| :--- | :--- | :--- | :--- |
| `split_rat_hour` | `bool` | `true` / `false` | Distinguish Early/Late Zi hour |
| `leap_month_strategy` | `string` | `"split"` / `"current"` / `"as_next"` | `split`=Divided by 15th, `current`=Counted to previous month, `as_next`=Counted to next month |
| `wu_hu_dun_boundary` | `string` | `"lunar"` / `"solar"` | Foundation for Five-Tigers-Chasing-Month stems |
| `sihua_boundary` | `string` | `"lunar"` / `"solar"` | Foundation for birth year SiHua |
| `childhood_decade` | `string` | `"skip"` / `"regular"` | `skip`=Jumping rule sect, `regular`=Year-by-year consecutive progression sect |
| `flowLimit_boundary` | `string` | `"lunar"` / `"solar"` | Bounding calendar choice for Flow constraints (Months/Days) |
| `enable_historical` | `bool` | `true` / `false` | Enable safeguards for ancient historical calendars |

---

### 6. `masters.json` — Ming Master / Shen Master Origins (Optional)

The Ming Master checks the Ming Palace's Earthly Branch index. The Shen Master checks the birth Year's Earthly Branch index. `boundary` controls whether the Shen Master fetches from the Lunar year or the Solar Term year.

```json
{
  "ming_zhu": {
    "table": { "0": "tanlang", "1": "jumen", ... }
  },
  "shen_zhu": {
    "boundary": "lunar",
    "table": { "0": "lingxing", "1": "tianxiang", ... }
  }
}
```

## 3. Using the Compilation Tool to Convert JSON to Dart Files

Once you have tweaked your JSONs and placed them in a directory, you can use the built-in compilation tool to pack all the JSON files in that directory into a single `.dart` file at once. This caters to convenient importing from your application:

```bash
# Default Usage (Compiles assets/config/default/ to lib/src/config/default_jsons.dart)
dart run tool/compile_jsons.dart

# Custom Usage (Compiles your own JSON directory to a specific output file and class name)
dart run tool/compile_jsons.dart <InputDirectory> <OutputFile> <DartClassName>
```

**Example:**
```bash
# Compiles assets/config/my_rules/ into lib/my_ruleset.dart, generating the MyRuleset class
dart run tool/compile_jsons.dart assets/config/my_rules lib/my_ruleset.dart MyRuleset
```

**Parameter Clarification:**
- `<InputDirectory>`: Where the JSON files reside.
- `<OutputFile>`: Where to place the generated `.dart` file.
- `<DartClassName>`: The **class name** within the generated file.

**Relation Between Parameters and Generated Code:**
If you execute: `dart run tool/compile_jsons.dart assets/config/rules lib/my_config.dart MyStyle`:

The content inside `lib/my_config.dart` becomes:
```dart
class MyStyle {  // This is the <DartClassName> you defined
  static const String stars = r""" ... """; 
  // ...
}
```

> [!NOTE]
> The tool automatically converts filenames to camelCase representing variable names:
> `flow_stars.json` → `MyRuleset.flowStars`, `main_rules.json` → `MyRuleset.mainRules`, etc.
